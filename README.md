# 矿山尾矿库监测计划与异常处置审阅平台

基于Angular、Angular Material、NgRx、Angular Router、RxJS、HttpClient、MapLibre GL、Turf.js、Nx和TypeScript的独立前端工程。无后端时自动使用本地模拟数据，界面内操作保留版本和审计。

## 功能

- 位移、水位、渗流、降雨监测点，MapLibre测点图层和Turf巡检路线长度。
- 报警值、变化速率与阈值版本查看。
- 异常队列、现场复核、证据、复测评估和专业异议并存。
- 处置方案、重大异常应急联动、负责人审批和关闭条件校验。
- 原始读数只读，所有修订形成独立版本和审计时间线。
- JSON审阅包导出。

## 调度令—异常—方案—应急联动一致性

汛期库水位调度令一改，相关实体在**同一个事务、同一个快照版本**内联动，杜绝“联动已启动、方案仍旧版”的半成品：

- **调度令生效**：旧令废止、新令生效；各开放异常按新令重算级别并留痕。
- **受影响方案失效重算**：级别档位变化、或方案所依据旧令被废止时，旧方案整体置“已失效”并入历史（保留签批与依据），按新令重算新版方案待签批。
- **已启动联动保留原依据**：联动的启动方案/调度令/快照版本永久冻结不改，只向其追加一次“调度令变更复核”，可维持/升级/解除。
- **未完成项先停住**：未完成处置任务一律暂停冻结，禁止推进；待新方案签批后按新依据解冻恢复。
- **并发签批只过一份**：签批带“打开时的方案版本+快照版本”，已有人签批或依据版本已变则不通过，后到者转草稿，草稿同时记录尝试时与当前依据版本。
- **写入失败可恢复**：每次写入先在内存推演为完整一致的整版快照（暂存），提交成功才整版发布；失败则看板/详情/审阅包仍显示上一已发布版本，暂存保留可重试或放弃。界面提供“模拟下一次写入失败”开关。
- **同版展示**：看板、异常详情、审计与导出审阅包都只读当前已发布快照（`snapshotVersion`），并由一致性自检兜底。

核心事务逻辑在 `apps/tailings-monitor/src/app/domain/transitions.ts`（纯函数），可用 `npm run verify` 跑 42 项端到端一致性断言。

端口为`18462`。

```bash
npm install
npm run build
npm run dev
```
